# Backport162

Backports iPadOS 16.2 (20C65) Stage Manager and external display behaviour to iPadOS 16.0 (20A8372), rootless (Dopamine).
Since 0.7.5 the former ExtendedDisplayEnabler tweak is part of this package (the Extended display provider registration and the saved mirror / extended choice); installing this package removes `com.infernowolf19.extendeddisplayenabler`.

- `WORKLIST.md`: every method whose logic changed between the two builds (generated by body-diffing both SpringBoards).
- `CLASS_DELTA_NAMES.txt`: classes/methods added or removed in 16.2.
- `specs/`: reconstructed 16.2 behaviour per class, and findings per group.

## Features in this build (0.6.0) — everything is on by default

0.6.0 integrates the reconstruction packages (groups 1b, 1c, 2, 2b, 3, 3b, 4b) on top of the 0.5.x external-display work. A feature is switched off with the file `<jbroot>/tmp/Backport162.off.<switch>`; everything with `<jbroot>/tmp/Backport162.off`. Every feature is on by default; the only two opt-ins (`edunative`, `methodology0`) are alternatives that would replace a 16.2 default. The tweak does nothing on any build but 20A8372. Source file in brackets.

### Backport162PTR (pointeruid dylib of the same package) [PTR.x]

Runs only inside the `pointeruid` executable (filter `Executables = pointeruid`, arm64e, build 20A8372 only). Ports three of the four 16.1 multi-display changes of pointeruid that the real 16.0 binary lacks (specs/POINTER-PIXELS-0.7.4.md); aimed at the stale pixels on the display edge when the pointer leaves the extended display. Effect on the pixels is a guess (about 25 %). `killall pointeruid` (or a userspace reboot) after installing or after creating / removing a switch file. Log lines `[Backport162PTR]` via NSLog (Console / idevicesyslog), also in `Backport162.log` with `Backport162.debug`.

### Notes

* SwitcherDismissFix 0.3.0 ports one class that group 1c also builds (`SBContinuousExposeToHomeSwitcherModifier`); whichever loads first creates it. Remove SwitcherDismissFix when you test this build.
* ExtendedDisplayEnabler 0.2.2 is merged into this package (0.7.5, specs/EDE-MERGE-0.7.5.md): its provider registration is EDE.x (`ede_provider`), the three other selectors it hooked are hooked once, by `autoext` / `mirrorsvc` in Group4Connect.m. `control` has `Conflicts` / `Replaces` / `Provides` `com.infernowolf19.extendeddisplayenabler`, so installing this package removes it. Not carried over: its crash-loop guard (it switched every hook off after five short-lived launches, whatever the cause) and its own log / kill-switch / debug files (`Backport162.off`, `Backport162.off.ede_provider`, `Backport162.debug`, `Backport162.log` replace them).
* Saved choice: CFPreferences domain `com.infernowolf19.backport162`, key `choice` (`extended` / `mirror`), written when the Settings switch or the education alert is used. On the first start without it the old value in `com.infernowolf19.extendeddisplayenabler` is read and copied (the old domain is left alone). Delete the key to go back to the automatic decision (`defaults delete com.infernowolf19.backport162 choice` as mobile, then respring).
* A switch for a sub-piece can be created while running (hooks re-check once a second); pieces that are installed at launch (class creation, `directhook`, `g2bproto`) need a respring.

## Switches (under the jailbreak root, i.e. `/var/jb/tmp/...`)

- `Backport162.off` disables everything; `Backport162.off.<feature>` disables one feature (names in the tables above). Hook behaviour is checked at most once a second, no respring needed; `nilock` and `directhook` are installed at launch, so those two need a respring after creating their `.off` file.
- `Backport162.debug` turns logging on (`Backport162.log`, rotated at 256 KiB). Logging is off by default.
- The tweak does nothing on any build other than 20A8372.

## Review notes (0.5.1)

An independent review of 0.5.0 (`specs/REVIEW-0.5.0.md`) found and 0.5.1 fixes: the wake gesture was never armed (16.0's external-display gesture manager refused type 0x42), `nilock` lacked a required delegate method, the pointer sniffer ignored real mouse touches, a cancelled pointer touch left `gesturegate` stuck, `directhook` now patches after the PC-relative `cbz` and signs the trampoline pointer for arm64e, and the `lockedptr` hook was deleted (a no-op on 16.0 and not thread-safe).
Still unverified without a device: whether backboardd 16.0 blanks an external display through `BKSDisplayServicesSetDisplayBlanked`, and the hooking library's behaviour for `directhook`. If either misbehaves create `Backport162.off.nowindow` / `Backport162.off.directhook` (the latter needs a respring).


## Debugging 0.6.x
Everything except the opt-in list in Tweak.x is on. To bisect a misbehaviour, disable one feature at a time with an empty file
`/var/jb/tmp/Backport162.off.<name>` (names in the table above) and respring; `Backport162.off` disables the whole tweak.

## Crash recorder
The tweak writes its own crash report to `/var/jb/tmp/Backport162.crash` (signal, fault address, registers, backtrace as `image+offset`;
uncaught Objective-C exceptions with reason). Use it when ReportCrash produces no `.ips`.
