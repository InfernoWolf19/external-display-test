# FEATURES-0.7.9: feature-level completeness audit of the 16.2 port (head 1ec6584 + merge e8a0299)

Independent, read-only audit: iPadOS 16.0 (20A8372, dyld cache + the device's own FeatureFlags / SpringBoard.app resources) against iPadOS 16.2 (20C65 cache + IPSW). Static analysis only, nothing run on a device. Addresses are 16.0 / 16.2 vm addresses.
Status words: IMPLEMENTED-DEVICE-CONFIRMED (named so in OPEN-ISSUES / the brief), IMPLEMENTED-UNTESTED, PARTIAL, MISSING. Evidence tags: [D] disassembled by me, [S] taken from an existing spec / source read, [N] only the class/method/string delta (name-level, behaviour not decoded).

## 0. How the audit was done, and what it covers

* Class/method deltas (ObjC dumps, 16.0 vs 16.2): SpringBoard (+2282 added methods, 940 of which have no selector name in our sources; the rest are renames/refactors), UIKitCore, SpringBoardFoundation, SpringBoardServices, FrontBoard(Services), BackBoardServices, QuartzCore, DisplayAndBrightnessSettings (Settings), AVKit, MediaPlayer, MediaControls, SpringBoardHome, SpringBoardUIServices. backboardd/pointeruid: existing spec POINTER-CROSS-0.7.4 re-read, not redone.
* Body diff of ALL 36 330 methods common to both SpringBoards (the older WORKLIST covered only 356 methods of ~66 Stage-Manager classes): 1 466 logic-changed (1 347 of them in named ObjC classes other than destructors); see section 5 for the classes the old list never looked at.
* FeatureFlags: the device's real 16.0 `/System/Library/FeatureFlags` against 16.2 (1201 vs 1277 flags), SpringBoardFoundation `SBF...Available` code, UIKit `os_feature` users.
* Strings: SpringBoard.loctable (16.0 from the device, 16.2 from the IPSW), DisplayAndBrightnessSettings loctables (ExternalDisplays, ContinuousExpose), SpringBoardEducation loctable.
* Our code: every claim "our code" below was grepped in `Backport162/*.x|*.m|*.h`; hooks were read where marked [S]/[D].

Headline: the SpringBoard side (switcher, layout, window management, display lifecycle, pointer routing) is broadly ported. The remaining gaps are (a) everything that lives in OTHER processes (UIKit inside every app, Settings, the HUD service), none of which the tweak is loaded into (filters: `com.apple.springboard`, `com.apple.AVKit`, backboardd, pointeruid, plus SMT/SPK), (b) a set of small per-display SpringBoard behaviours that 16.2 added to classes outside the Stage-Manager class list (transient overlays, recording indicator, keyboard suppression, in-call, remote alerts), (c) the monitor resolution/scale logic in SpringBoardFoundation/QuartzCore.

## 3. TOP-15 gap list with implementation outlines

Effort S < 1 day, M 1-3 days, L > 3 days; risk = chance of SpringBoard/app crash or regression.

1. **T1 Overlays on the embedded display (S, low).** Add `prefersEmbeddedDisplayPresentation -> YES` to the five 16.2 classes (class_addMethod on the metaclass-free instance side, `+initialize`-safe, `BP_OnName("embedoverlay")`). Re-check the two 16.2-only call sites (0x1c7352cb4, 0x1c7893af8) for extra logic (interactive Spotlight begin; transition-request overlay context) and mirror them if they change the display choice. Device check: Cmd-Space / Control Centre swipe with the pointer on the monitor must open on the iPad.
2. **K1 Keyboard on the monitor (L, high).** New UIKit-in-app dylib (filter `com.apple.UIKit`, 20A8372 build guard, executables excluding SpringBoard/backboardd). Port `UIKeyboardVisualModeManager softwareKeyboardAllowedOnExternalScreen/textEntryFocusOnExternalDisplay`, `UIKeyboardSceneDelegate keyboardScreen/textEntryFocusOnExternalDisplay/_windowHostingScene:...`, arbiter-client scene foreground tracking. Start log-only (which path 16.0 takes for a field on the monitor). Risk: every app; ship behind `Backport162.off.uikit`, crash breadcrumb like `g2bproto`.
3. **D1 Monitor scale mapping and mode choice (M, medium).** Re-implement `SBDisplayScaleMapping withDisplay:` 0x18ee471c4 (walk `availableModes`, scaleMethod, `_defaultScale` 0x18ee48c28) by hooking the 16.0 `+withDisplay:allowWirelessDisplays:` 0x18eba64cc and the new init; first collect `SBLogDisplayScaleMapping` for both builds (os_log is in the 16.2 function already) on the user's monitor to see if results differ. 4. **E1 Education session (S, verify first).** On the device: does `/Applications/SpringBoardEducation.app` (16.0) contain `EXTERNAL_DISPLAY_FIRST_TIME_ONBOARDING_TITLE`? If not, flip `edunative` to default and use the 16.2 wording (strings in section 4), or bundle the strings.
5. **Z1 Labels (S, low).** Embed the 16.2 en strings (and optionally all languages, extracted from the 16.2 loctable) and have the title hooks use them when the 16.0 table lacks the key: "Enter Full Screen" / "Zoom", `ENTER_FULL_SCREEN_DISCOVERABILITY`, Control Centre "External Display" / "Stage Manager On|Off" (SMT may already own the last two).
