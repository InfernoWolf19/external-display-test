## Verified equivalent (no change needed)
* status bar `isFrontmostStatusBarPartHidden:`: 16.0 and 16.2 bodies differ only in two `[SBMainSwitcherControllerCoordinator sharedInstance]` calls replaced by the window scene's `switcherController` (selector sequences diffed); the dynamic-extent redirect of `layoutState`/`unlockedEnvironmentMode` is the same.
* PiP per display (manager, tap recognizers, style notification, enhanced windowing), hosted keyboard controller: structure matches 16.2; gesture numbers 0x77/0x78 are the 16.0 enum.
* `supportsMultiWindowLayoutsForSwitcherWindowManagementStyle:displayIdentity:` identical in both builds, so the "multiple windows not supported" banner/log is 16.2 behaviour (predicates identical).
* `_didUpdateSettingsWithDiff:previousSettings:` reset of the orientation request state, canvas-size poster/observer: unchanged.

## CANNOT (precise reason) and closest equivalent
* Privacy preflight (g3b_preflightlog): the gate needs `PrivacyDisclosureCore` (PDCPreflightManager, absent from the 16.0 cache), the consent UI `com.apple.PDUIApp` (not in 16.0) and FrontBoard changes (`FBApplicationUpdateScenesTransaction` waits for `_isReadyToLaunch`). The decision rule (`isPreflightFeatureEnabled`, `regulatoryPrivacyDisclosureVersion`, consent file) is ported and logged per launch. On every device where 16.2 evaluates it to NO (green-tea off) 16.2 and this port behave identically (launch proceeds); where it would be YES nothing can ask for consent.
* SBSwitcherController `Did` window-management-style callback = `-[SBMainSwitcherControllerCoordinator _rebuildCurrentWindowingModeCompatibleAppLayoutsIfNecessary]` (0x1c76db498): needs the 16.2-only coordinator ivar +0x18, `+_filterAppLayoutForChamois:` and `enumerateSwitcherControllersWithBlock:` (app-layout model of group 2). Will-callback is ported.
* Banner strings: the 16.2 keys `MEDUSA_BANNER_ERROR_*` exist only in 16.2's SpringBoard.loctable (no 16.2 app bundle available); 16.0 keys with the same wording are the fallback.
* Per-scene `_classicAppPhoneOnPadPrefersLandscape`: the handle accessor forwards to the app property because the 16.0 consumers (4 call sites in other classes) read the app property; for the single-scene classic app the value is the same.
* PiP morph (`createAndRegisterPictureInPictureMorphAnimatorController...appLayout:layoutRole:appLayoutBoundingBox:`, `_setupPIPMorphingIfNeededForTransitionContext:response:`): driven by a modifier response of the 16.2 switcher stack (group 1/2), not by SBPIPController; open item for the switcher agent.
* `windowScene:didUpdateCoordinateSpace` analytics event 60, `_sbSceneManager` transient setting, `screenBoundsIgnoresSceneOrientation` (UIKit), SBSwitcherTraitsAssistant scene-orientation-request guide: no 16.0 consumer / enum differs; unchanged.
* `shouldKeyboardBeWindowSizedForHostWithIdentity:` has no 16.0 caller (not in the 16.0 `_UIKeyboardArbiterOmniscientDelegate`).

## Unsure
Zoom: 16.2 never toggles back from policy Largest (re-press re-requests the same state); un-zoom happens through resize/other 16.2 paths. Menu rebuild and grid sort direction (comparator args read as (a,b)) are static only.

## Zoom un-zoom (0.7.1, after device test of 01771d6)
Device: first press zooms, second press does nothing, menu title stays "Zoom".
Re-investigation of 16.2 (all static): the Zoom block (0x1c77cd2e8) always requests (Largest, Unspecified, Unspecified); `AllowingSmallestSize` (0x1c79542fc) has exactly one 16.2 caller (the resize modifier); `sizingPolicy` has no new reader; request storage (`setRequestedLayoutAttributes:forEntity:` 0x1c765b7c4, `_setRequestedFrontmostEntity:` 0x1c765b980), `setEntities:withPolicy:` (0x1c765b0b4), layout-state conversion and `sizingPolicyForDisplayItem:` (0x1c75a475c) are 16.0-identical; the calculator write-back derives policy from size only (`_SBPreferredDisplayItemSizingPolicy` 0x1c7954330: policy 2 with size != (1,1) -> 0, policy 1 stays); the frame code resolves policy 2 to the container only for an Unspecified size (0x1c75a3db8). Supported mask for a resizable app in Stage Manager is 5 (policies 0 and 2), so Largest = 2. `_isZoomed = (policy == Largest)` (0x1c77cbdf4) is consumed only by `updateContextMenuWithLayoutRole:...isZoomed:` (title key ..._ZOOM / ..._UNZOOM and image 10/11 chosen on every update, 0x1c790cac4). No 16.2 code that leaves the zoomed state through this item could be found, so un-zoom is not literally portable from 16.2.
Fix: G3C.x `G3C_ZoomRequest` toggles: current policy == Largest(mask) -> policy Smallest(mask) with the remembered pre-zoom attributed size (skipped when full size/Unspecified, then the 16.2 default window via Unspecified) and user size Unspecified; otherwise the 16.2 request, remembering the size first. G3.x `G3_ZoomTitle` hooks `-[SBTopAffordanceViewController updateContextMenuWithLayoutRole:...isZoomed:]` and sets `_maximizationAction.title` on every update (16.0 only set it at creation, which is why the title never changed): 16.2 key if present in the loctable, else "Unzoom" for the zoomed state and the 16.0 "Zoom" string otherwise. The 16.2 English strings are not available offline.
