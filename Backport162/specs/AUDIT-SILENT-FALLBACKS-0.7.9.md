# AUDIT: silent fallbacks, type mismatches, load-time code, armed overrides, signatures (0.7.9)

Why: bugs kept surfacing that needed device logs. Two found in one session show the class: (1) `G1C_WdDragging` / `G1C_WdProposedAll` accepted only `NSArray` but the coordinator answers an `NSCountedSet` copy and the VC an `NSMutableSet`, so the dragged layout was silently dropped (0efa07d); (2) `Y28Keyboard.x` constructor messaged `+[SBSceneManagerCoordinator mainDisplaySceneManager]` at dylib load, a boot hang (b6d6599). Earlier: a selector sent to the wrong receiver answered NO and caused unbounded re-entrancy. Common class: a ported body whose assumption fails and silently returns the stock / default value, nothing in the log.

Classes: A collection type mismatches, B silent fallbacks, C constructors / load-time code, D armed one-shot overrides, E wrong receiver / IMP signature, F caller / callee contract (card path first).

## 0. The anomaly channel (class B infrastructure)

* `BP_Anomaly(const char *tag, NSString *fmt, ...)` (BP.h, Tweak.x): appends `ANOMALY <tag>: <message>` to `<jbroot>/tmp/Backport162.log` always (no `Backport162.debug`). Cap 300 lines per process (+1 `ANOMALY (cap)` line), 40 per tag, a (tag, message) is written once, a (tag, format string pointer) is formatted at most 8 times (two table probes under a mutex before any allocation). Shares the file descriptor / rotation of `BP_Log` (`BP_LogLine`).
* `Y17_GuardOnce` (Y17Common.h) now hashes (tag, class name, what) into a lock-free table (no `NSString` per call; it runs on hot paths) and calls `BP_Anomaly`.
* every `GUARD...` `BP_Log` line (89 sites in 23 files) was turned into a `BP_Anomaly` with the GUARD(tag) as the tag (or `guard-<file>`); their `if (BP_LogEnabled())` guards were removed (the lines are rare by construction, and bounded by the cap otherwise).
* helpers that returned nil / 0 / NO for a missing selector (`BPX_*`, `BPY_*`, `G1B_Send*`): see section B.

## A. Collection type mismatches (class A)

Method: every `isKindOfClass:[NS{Array,Set,Dictionary,...}]` gate (83 sites in 24 files), every cast of a 16.0 return value to a collection. The real return types were taken from the class dumps (ivar / property types: `sb160n_objc.txt`, `sb162_objc.txt`, `BaseBoard_160.txt`) and from the disassembly of the producing method (a160.sh / a162.sh).

Proven types (evidence): `-[SBAppLayout allItems]` NSArray (16.0 0x1c5e30ee8, property getter of `_items NSArray`); `-[SBAppLayout leafAppLayouts]` NSArray (0x1c628cc5c builds `arrayWithObjects:count:`); `-[SBAppLayout itemsToLayoutAttributesMap]` NSDictionary (copy property); `-[SBTransitionSwitcherModifierEvent appLayoutsWithRemovalContexts]` NSArray (0x1c5fb7874 = `[_appLayoutToRemovalContext allKeys]`); `SBMainSwitcherControllerCoordinator._appLayouts` NSArray; `_hiddenRecycledItemContainers` NSMutableArray; `_visibleOverlayAccessoryViews` / `_visibleItemContainers` / `_liveContentOverlays` / `_leafAppLayoutsToAdjustedAppLayouts` NSMutableDictionary / NSDictionary; `SBChamoisLayoutAttributes.gridWidths/gridHeights` NSArray; `BSCompoundAssertion.reasons` NSSet (property type); `_continuousExposeIdentifiers` NSOrderedSet (16.0) vs NSArray (16.2) already converted by `G1C_AsArray` / `G1B_OverrideIds`; `-[SBFluidSwitcherViewController appLayoutsForContinuousExposeIdentifier:]` builds its answer by fast enumeration of `_unadjustedAppLayouts` into a fresh array (16.2 0x1c74373ec), root version `_adjustedAppLayoutsForAppLayouts:` array; the 16.0 caller of `transitionContextForLayoutContext:failedEntities:` passes `[NSSet setWithObject:]` (0x1c5f019bc); NSCountedSet / NSMutableSet for `draggingAppLayouts` / proposed layouts (the 0efa07d bug, fixed).

## C. Constructors and load-time code (class C)

Checked: the Tweak.x `%ctor` and its 33 `*_Setup` / `*_Early` callees, the 32 `Y*_Setup` constructors, `Z2O*` constructors, and (other dylibs) SMT.x, AV.x. Method: extracted every constructor body, flagged message sends and singleton selectors (`sharedInstance`, `sharedApplication`, `mainScreen`, `mainDisplaySceneManager`, `mainWorkspace`, `localDefaults`, `UIScreen`, `FBSDisplayManager`, `BPX_App()`, ...) in every function reachable from them.
* All 32 Y constructors only call `NSClassFromString`, `class_getInstanceMethod`, `BPX_Replace`, `class_addMethod`, `dlsym`, `BP_Log` / `BP_Anomaly`: clean.
* `EDE.x`: reads `sharedInstance` / `[UIApplication sharedApplication]` only inside hook bodies (`registerDisplayControllerProvider:` and after `_completeStartupAfterMainSceneConnect:`), never at load: clean.
* `G2B.m:1036` `sharedInstance` of `SBApplicationController` is inside an `imp_implementationWithBlock` body (runs at call time): clean.
* `Y2Gestures.x:148` `mainDisplayManager` is only a selector name.
* NOT pure reflection but known and deliberate: `BP2B_Early` sends `+class` to `SBSwitcherModifier` (runs that class's `+initialize`, which builds the protocol tables; must happen before any other message reaches a modifier class, comment in Tweak.x) and `G1B_MakeClass` sends `[sup class]` to the superclass of each run-time class (same reason). `+initialize` of a modifier base class creates no singleton and has run at load in every build since 0.7.0 (no boot hang).
* DEFERRED, not lazy: `G2G_Setup` (`G2G.x`) schedules `G2G_Register` with `dispatch_async(main queue)`; its first run is the first main run loop turn and sends `-multiDisplayUserInteractionCoordinator` to `[UIApplication sharedApplication]` (selector not present in the 16.0 class dump, so whether it is a plain ivar getter is UNPROVEN); on a miss it retries once a second up to 60 times and logs. `Z1_Setup` also only dispatches to the main queue (a watchdog thread, a timer, notify registration) and hooks `-[SpringBoard sendEvent:]`: no singleton. Status: G2G unproven, left as is (it has not hung a boot in any build; making it lazier would delay the stuck resize arrow fix).
* No constructor messages a SpringBoard singleton or live object: no offender found, nothing to fix.

## F. Caller / callee contract: the card path (first part of class F)

Result of the static analysis (no device log; the runtime cause of the tiny card is NOT proven):
* The VC side of the card path is byte-identical in 16.0 and 16.2 (`cmpm.sh`, only adrp page offsets differ): `layoutFrameForItemWithRole:inAppLayout:interfaceOrientation:forSnapshotView:` (16.0 0x1c5fd7ba0 / 16.2 0x1c7450da8), `snapshotSizeForItemWithRole:...inImageCache:` (0x1c5fd7708 / 0x1c7450910), `frameForPageViewOfContainer:fullyPresented:` (0x1c5e32db8 / 0x1c72a5224), `_updateShadowPathForIndex:` (0x1c5fdbd70 / 0x1c74550b4), `-[SBSwitcherModifier scaledFrameForLayoutRole:inAppLayout:atIndex:]` (0x1c61c3a30 / 0x1c76525a4). Contract: `idx = [[root appLayouts] indexOfObject:ADJUSTED layout]` (adjusted = `_leafAppLayoutsToAdjustedAppLayouts[leaf]`), `bounds = rect(0, 0, [_rootModifier frameForIndex:idx].size)`, `R' = [root frameForLayoutRole:role inAppLayout:ADJUSTED withBounds:bounds]`, only `R'.size` is used.
* The stock 16.0 grid / transition modifiers need no port: `SBGridSwitcherModifier`, `SBGridLayoutSwitcherModifier` (frameForIndex is a 12 byte stub in both), `_SBGridFloorSwitcherModifier`, `SBGridSwipeUpToSwitcherSwitcherModifier`, `SBGridToActiveAppLayouts...`, `SBHomeGestureToMixedGrid...`, `SBMixedGrid*` have the same `frameForIndex:` / `scaleForIndex:` / `frameForLayoutRole:` bodies in both builds (bodydiff `same`); `SBHomeToGridSwitcherModifier` gained two pass-throughs (`frameForLayoutRole:` 0x1c73db18c, `scaleForLayoutRole:` 0x1c73db488), already ported (`G1C_InstallHomeToGrid`). The frame / scale providers whose bodies differ are exactly the Stage Manager family (`SBAppSwitcherContinuousExpose`, `SBFullScreenContinuousExpose`, `SBContinuousExposeWindowDrag`, `SBInlineAppExposeContinuousExpose`, `SBContinuousExposeIdentifierSlide`, `SBRevealContinuousExposeStripOverflowGestureModifier`, `SBDisplayItemLayoutAttributesCalculator`), all ported (G1C / G2 / P1SW); the other differing callers of `frameForIndex:` / `scaleForIndex:` (`overlayAccessoryViewFrameForIconOverlayView:fullPresented:`, `activeCornersForTouchResize...`, window drag `handleGestureEvent:`) are ported (P1VC, G1C, ...).
* The contract change is inside `SBAppSwitcherContinuousExposeSwitcherModifier` itself. 16.0: `frameForIndex:` = `_frameForIndex:ignoringScrollOffset:` (0x1c636c5b0) whose size is `_scaledCardSize` (0x1c636cae0 = containerViewBounds x `gridSwitcherPageScale`), i.e. the SCALED card; `scaleForIndex:` about 1; `frameForLayoutRole:` = [super] (bounds derived). 16.2: UNSCALED window frame (`_frameForIndex:withScaleApplied:scrollOffsetApplied:` 0x1c78135dc: the compacted bounding box size centred on the scaled card) + `scaleForIndex:` = card scale, role frame ignores `bounds`. 16.2 also made that class a full floor (about 100 own query methods, no `didMoveToParentModifier:` grid child; 16.0 got them from the `SBGridSwitcherModifier` child).
* The port flips the contract PER CALL. The geometry answers gated on "a pile calculation exists and the layout is in it"; `frameForLayoutRole:` additionally needed the overlapping model / item; `_defaultCardScale` / `snapshotScaleForAppLayout:` gated on a THIRD predicate (`G1C_As_Usable`: `containerViewBounds` does not throw). A modifier whose pile calculation threw on another query (`G1C_As_Calc` nil) but still answered `containerViewBounds` therefore gave the 16.2 card scale on top of the 16.0 SCALED frames: a card scaled twice. Fixed (changed behaviour, only in that mixed state): both scale answers now use `G1C_As_PileMode` = piles on AND Usable AND a calculation exists (same predicate as the frames).
* Every fallback to the 16.0 body while piles are on is now announced once (`ANOMALY g1c-piles: <selector> answered by the 16.0 body (SCALED frame contract) while piles are on: <why> [<class>]`, reasons: no pile calculation / no app layout at the index / the layout is not in the pile frames / the overlapping model / item of the role is missing). 16.2 has no fallback, so any such line is a candidate for the tiny card; together with the debug lines `[g1c] frameForLayoutRole falls back ...` and `[y30] snapshot frame ...` it names the disagreeing gate on the next device log.
* NOT proven: whether a pile layout fell back in the reported tiny card case (no log).
