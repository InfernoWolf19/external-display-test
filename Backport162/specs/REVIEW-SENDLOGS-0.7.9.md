# Review of "Send logs" (0.7.9): adversarial read of RPT.x, the Settings pane, the packaging

Scope: `RPT.x`, `Backport162Prefs/`, `layout/Library/PreferenceLoader`, `Makefile` (bundle part), `control`, the workflow's Backport162Prefs step, `layout/DEBIAN/postinst`, `.github/scripts/aptrepo.py` (read only). Method: every line of `RPT.x` and the controller read twice; the Preferences framework of the 16.0 dyld cache (`/System/Library/PrivateFrameworks/Preferences.framework/Preferences`, present in the cache, classes `PSListController`, `PSSpecifier`, `PSEditableTableCell` (= the cell class behind `PSEditTextCell` / `PSSecureEditTextCell`; those two are cell type *names* of the plist, not classes), `PSRootController`) disassembled for what the pane relies on; the Theos checkout read for the packaging; the stub-based clang syntax check of the author re-run (`-Wall -Wextra`, no warnings). Nothing ran on a device.

## 2. Defects fixed

| id | defect | fix (commit) |
|---|---|---|
| D1 | `gRPTRunning` and `gRPTSerial` were two separate atomics. A stale `RPT_Finish` of a job that already answered (the `@finally` of `RPT_RunJob`) tested "running == 1 and serial == mine" without a common step with the main queue's "CAS running 0 -> 1, then serial + 1": in the instant between the two operations of a new request the stale call matched, published a bogus "internal error" answer and cleared the new job's flag (new job then ran without a flag, a third request started a parallel job). Window of a few instructions, but possible. | One 64-bit state word `serial << 2 | idle / running / answering`; every transition is one compare-and-swap, `RPT_Finish` takes running -> answering (exactly one winner), publishes, stores idle, posts `.done`. (a258ff8) |
| D2 | *Share instead* posted the normal request, so SpringBoard uploaded whenever it saw a valid repository + token (the spec claimed "no upload"). Reachable when Settings' test and SpringBoard's test differ (field committed between the two reads). | Second Darwin name `report.request.local`; the job collects, writes the local file and answers without reading repo / token for any upload. (a258ff8, 697b32e) |
| D3 | A symlink at a log / crash location would have been followed (`open` / `stat`): another process able to write `<jbroot>/tmp` (it is not sandboxed away from tweak code) could point `Backport162.log` at the preferences plist and get the token into the report. | `O_NOFOLLOW` on every report read, `lstat` for crash files, `unlink` + `O_EXCL|O_NOFOLLOW` for the local `.tmp`. (a258ff8) |
| D4 | The CrashReporter scan looked at only 2000 directory entries in arbitrary order; a device with many analytics / jetsam files could miss the newest SpringBoard crash. | 20000 entries (names are only compared, `lstat` only for matches). (a258ff8) |
| D5 | Token defence in depth: nothing in the code puts the token in the report, but the guarantee relied on that alone. | The token is read at the start of the job and every section is scanned (`memmem`) and scrubbed (`[removed]`) before gzip. (a258ff8) |
| D6 | Footer said "so the report id can be looked at" and said nothing about what is in the files or about public repositories. | Footer rewritten (collected items, "bundle identifiers, app and display names, paths, iPad model", PRIVATE repository, Share never uploads, logging off by default). (697b32e) |
| D7 | `Depends: preferenceloader`: if the user's repositories cannot resolve the package, apt refuses the whole install / update of Backport162 over a Settings pane. | `Depends: mobilesubstrate`, `Recommends: preferenceloader`. Without PreferenceLoader only the pane is absent. (4772390) |
| D8 | Spec arithmetic "well below 12 MiB" was wrong (gz + base64 + body coexist: 15 MiB at the 4 MiB cap, 3 MiB typical); report NOTE said the log holds "always written lines" but `BP_Log` writes only with `Backport162.debug` (the report would have misled the reader); dpkg status path `<jbroot>/Library/dpkg/status` is the Elucubratus location, rootless Procursus uses `<jbroot>/var/lib/dpkg/status`. | Texts corrected, both dpkg paths tried. (a258ff8, 47bde76) |
| D9 | Settings waited 150 s; the SpringBoard side can need ~10 s to collect plus 130 s upload wait. | 170 s. Also: Share rejects `..` path components; button label "Working..." (it covers the upload too). (697b32e) |

Checked and found correct (no change): the `-specifiers` override with its guard (the base `-[PSListController specifiers]` loads the plist named by the specifier's `plist` property, here none, and stores an empty array; nothing in `setSpecifiers:` / `prepareSpecifiersMetadata` / `reload` calls `-specifiers` again, only `viewDidLoad`, `reloadSpecifiers`, `specifierForID:` do, so the guard never hides real specifiers); `PSEditableTableCell` commits to the preference domain in `textFieldDidEndEditing:` (`endEditingAndSave` -> `controlChanged:` -> setter) which `endEditing:YES` triggers synchronously, before the button's deferred step; `performButtonActionForSpecifier:` calls the `action` selector on the specifier's target (the controller) with the specifier as argument (and catches exceptions itself); `reloadSpecifier:animated:` ignores a specifier that is not in the list; the secure cell turns auto-capitalisation and auto-correction off in `refreshCellContentsWithSpecifier:` (a capitalised first letter would corrupt the token) and the repository cell takes the specifier's default `autoCapsType` 0 (= none) plus `noAutoCorrect`.

## 3. What exactly leaves the device (only after "Send logs now", to the typed repository)

* `system` section: report id, local time + zone name, tweak version, `kern.osversion` (20A8372), `kern.osrelease`, `hw.machine` (iPad14,x), `operatingSystemVersionString`, uptime, SpringBoard pid, whether `Backport162.debug` exists, the names of `Backport162.*` files in `<jbroot>/tmp`, the names (paths) of loaded images containing "Backport162" (these show the random `/private/preboot/<hash>/dopamine-xxxx/` jailbreak root).
* `Backport162.crash` (own crash recorder, tail 128 KiB), `Backport162.log` (tail 2 MiB), `.log.1` (tail 1 MiB), `Backport162.daemon.log` (tail 256 KiB): whatever the tweak logged, with `Backport162.debug` on this includes scene identifiers / bundle ids of apps, display identifiers, frames, layout dumps (G2I). Without the flag these are empty / missing.
* up to 4 crash reports of the last 3 days (SpringBoard, backboardd, pointeruid, mediaserverd, audiomxd, Preferences), the first 200 KiB each, plus an index of up to 20 file names. An `.ips` file starts with a one-line JSON header (app name, bundle id, version, build, OS version, incident id) followed by the report JSON: process path, launch time, parent process, model code, OS build, kernel version, exception / termination, all threads' frames with image names and offsets, used images with UUIDs and paths, and the device's pseudonymous `crashReporterKey`. It does not contain the device name, Apple ID, serial number or UDID. Crash reports of Preferences / SpringBoard can name the pane that crashed and, in frames, app-specific class names.
* Not in the report: preferences, token, environment, command lines, file contents other than those listed, other processes' memory.
* GitHub also sees the account of the token, the IP address of the iPad, and the time.

## 4. Open items

* O1 (device) Does the bundle load in Settings with `-undefined dynamic_lookup` on arm64e (superclass `PSListController` bound by flat lookup)? If Settings shows no "Backport162" entry or logs a dlopen failure, link against a stub of Preferences.framework instead. Check on the device: `/var/jb/Library/PreferenceBundles/Backport162Prefs.bundle`, the entry in Settings > (bottom) Tweaks.
* O2 (device) cfprefsd visibility Settings <-> SpringBoard for this domain, sandbox of SpringBoard for reading `/var/mobile/Library/Logs/CrashReporter` and writing `<jbroot>/var/mobile/Library/Caches/Backport162Reports`, sandbox of Settings for reading that report (otherwise *Share report...* is not offered), `NSURLSession` from SpringBoard.
* O3 (device) Contents API on a repository with only a README (expected 201), and on an empty one (not tested; the setup requires a README).
* O4 (design, not done) No check that the repository is private. A `GET /repos/<repo>` before the upload could refuse a public one (`"private": false`); adds a request and a failure mode, so left to a decision.
* O5 (UX, not done) If SpringBoard is not listening (tweak off, wrong build, safe mode) the pane shows the spinner for 170 s before "SpringBoard did not answer". An acknowledgement notification with a ~10 s deadline would shorten it; not added to keep the Settings half small.
* O6 (accepted) Redirects (a renamed repository answers 301 / 307) are followed by NSURLSession without a delegate; GitHub does not redirect cross-host. A public-API surprise would show as "HTTP 3xx".
* O7 (accepted) The token sits in plain text in the preferences plist (and so in a backup of the device); use the narrow fine-grained token and revoke it.
