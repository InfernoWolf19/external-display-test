# PORT-G1C-0.7.0: fallbacks removed / ported in G1C.x (20A8372 -> 20C65)

Addresses: 160 = 20A8372, 162 = 20C65. PORTED = the 16.2 logic is now the normal path. CANNOT = not portable in this file (reason given). UNSURE = ported but a detail is a judgement call.
Every kill switch is `Backport162.off.<name>` (BP_OnName). Everything is default ON.

## 0. Crash that started this work (round 1)
`NSInternalInconsistencyException: Can't add child modifier <SBFilteringSwitcherModifier> with key: 'Gesture' to <BP162ContinuousExposeWindowDragRootSwitcherModifier>`.
Cause: the gesture root adds its "Gesture" child at gesture phase 1 and finishes it through `[gestureModifier setState:1]` in `handleTransitionEvent:`; a second phase-1 event (second drag started before the first child was reaped in the post-dispatch pass) hits `addChildModifier:atLevel:key:` with the key still taken. 16.2 has the same latent hole (it relies on the finished child being removed by the post-dispatch pass), so the port keeps 16.2's lifecycle and adds ONE logged last-line guard on the three BP162 gesture roots (`G1C_GR_Guard` / `G1C_GR_GM`: a stale finished child is removed before the new one is added; logs under BP_LogEnabled()).

## 6. CANNOT / not done here (cross-agent needs)
1. `-[SBFullScreenFluidSwitcherRootSwitcherModifier transitionModifierForMainTransitionEvent:]` 0x1c762c998 (4264 B vs 160 0x1c61a1440 4036 B). Deltas seen in the listing diff, none of them ported by anyone: `isChamoisWindowingUIEnabled` flag stored at the top; `setShouldForceDefaultAnchorPointForTransition:` on the icon zoom / centre zoom children; `initWithTransitionID:appLayout:layoutRole:chamoisWindowingUIEnabled:`; `initWithTransitionID:direction:fullScreenAppLayout:deckModifier:`, `initWithTransitionID:direction:multitaskingModifier:`, `isEnteringAnyPeekEvent` + `setFullScreenTransition:`; `isCenterWindowToSlideOverEvent` / `isCenterWindowToNewSplitViewEvent` order; PIP restore with `toLayoutRole:`. G1B owns the CE-root subclass hook only.
2. `-[_SBHomeScreenFloorSwitcherModifier handleTransitionEvent:]` 0x1c750c194 (1468 B vs 1276 B): same PIP / icon zoom creator changes; new forwarders `clippingFrameForIndex:withBounds:` / `clippingFrameForLayoutRole...` (20 B each) are covered by G2B's defaults.
3. Producer of `morphingPIPLayoutRole`: `-[SBMainSwitcherControllerCoordinator _shouldMorphToPIPForTransitionContext:outForLayoutRole:]` 0x1c76d4ea0 (coordinator, not in 16.0). The role is only stored by the decoded modifiers (never read), so a missing producer has no visible effect. The consumer of `SBSetupPIPMorphingSwitcherEventResponse.appLayoutBoundingBox` is the view controller's `_setupMorphAnimatorIfNeededForEntity:pipCoordinator:appLayout:appLayoutBoundingBox:` (16.2) which belongs to the VC group; until it reads the new property the response is harmless.
4. `draggingAppLayoutsForContinuousExposeWindowDrag` / `proposedAppLayoutsForContinuousExposeWindowDrag`: coordinator state (cross display). G2 stubs them; the drag destination answers with its own layouts (single display). Multi-display drags between switchers therefore degrade to single display.

Needs from G2/G2B that this file now requires (all present): `attributedSize`, `initWithContentOrientation:lastInteractionTime:sizingPolicy:attributedSize:normalizedCenter:`, `attributesByModifyingNormalizedCenter:`, `sizeInBounds:defaultSize:screenEdgePadding:`, `overlappingModelForAppLayout:` (1 argument), `widthThresholdToHideStrip`, `boundingBox`, `stageArea`, `isItemFullyOccluded:` / `isItemPartiallyOccluded:` / `isItemCoveredByFullyOccludedPeekingItem:`, `partiallyOccludedStageScaleForItemWithSize:`.
